# Piggy Bank 기능 명세

간단한 개인용 가계부 안드로이드 앱 **Piggy bank**. 각 사용자가 자신의 구글 계정으로 로그인하고, 데이터는 기기 내부 DB에 저장하며 사용자 본인의 구글 드라이브에 백업한다.

## 0. 확정 사항 요약

| 항목 | 결정 |
|---|---|
| 플랫폼 | Android (Kotlin, Jetpack Compose, Material 3) |
| 최소 지원 버전 | Android 8.0 (API 26) |
| 로컬 저장 | Room (SQLCipher로 암호화) |
| 원격 저장 | 사용자 본인의 Google Drive `appDataFolder` (백업/복원 용도) |
| 동기화 범위 | 1인 1기기. 드라이브는 백업과 복원 용도 |
| 로그인 | 필수 (Google 계정) |
| 탭 구성 | 가계부 / 자산 / 설정 |
| 자산 구조 | 2단계 (자산 그룹 > 세부 자산) |
| 거래 유형 | 수입 / 지출 / 이체 |
| 통화 | 원화(KRW), 소수점 없음 |
| 배포 | push할 때마다 자동 빌드 → GitHub 릴리스 `dev-latest`. 설치 링크로 최초 설치, 이후 앱 안에서 업데이트 (12장) |
| 디자인 | 아기자기한 파스텔 톤, 돼지 캐릭터(고른 앱 아이콘 그림). 테마 8가지·앱 아이콘 9가지 중 선택 (10장 참고) |
| 제외 | 카테고리, 신용카드(부채), 앱 잠금, 백업 파일 추가 암호화 |

## 1. 첫 실행 및 로그인

1. 로그인 화면: 돼지 캐릭터(고른 앱 아이콘 그림)와 "Google 계정으로 시작하기" 버튼
2. 안드로이드 계정 선택 화면에서 Google 계정 선택
3. Drive 권한(`drive.appdata`) 동의 화면 (처음 한 번)
4. 드라이브에 백업이 있으면 "드라이브에 백업이 있어요" 팝업 (바깥을 눌러 닫을 수 없음)
   - **불러오기** → 기기 데이터를 백업 데이터로 바꾼다
   - **불러오지 않기** → 지금 기기 데이터를 그대로 쓴다. 다음 백업 때 드라이브 백업이 기기 데이터로 바뀐다
5. 기기에 자산 그룹이 하나도 없으면 기본 자산 "현금 > 지갑"(초기 잔액 0원)을 만든다
6. 가계부 탭으로 이동

- 로그인하지 않은 상태에서는 앱을 사용할 수 없다.
- 로그아웃하면 로그인 화면으로 돌아간다. 로그아웃해도 기기 내 데이터는 유지하고, 예약된 자동 백업은 취소한다.
- 다른 계정으로 다시 로그인하면 4번처럼 그 계정의 백업을 불러올지 묻는다.
- Google Cloud 설정 방법: [GOOGLE_CLOUD_SETUP.md](GOOGLE_CLOUD_SETUP.md)

## 2. 가계부 탭

```
 ◀  2026년 10월  ▶
 수입 3,000,000 · 지출 452,000 · 합계 2,548,000   [👁]
──────────────────────────────────────────────
 10.09 (금)                              -12,000
   점심          은행 > 국민              -12,000
   이체          국민 → 신한              500,000
 10.08 (수)                               ...
                                            (+)
```

### 월 이동
- 상단 ◀ ▶ 로 이전 달/다음 달 이동. 기본값은 이번 달.

### 월 요약 (1줄)
- `수입 · 지출 · 합계`를 한 줄로 간략히 표시한다. 합계 = 수입 − 지출이며, 이체는 포함하지 않는다.
- 오른쪽 눈 모양 버튼으로 숨기기/보이기를 전환한다.
  - 숨기면 금액이 `••••`로 가려진다.
  - 숨김 상태는 앱을 다시 켜도 유지한다.

### 거래 목록
- 날짜별로 묶어 최신 날짜부터 표시한다. 같은 날짜 안에서는 최근 입력이 위에 온다.
- 날짜 헤더에는 그날의 합계(수입 − 지출)를 표시한다.
- 각 항목
  - 내용 (비어 있으면 "수입" / "지출" / "이체")
  - 자산: `그룹 > 자산`, 이체는 `출금 자산 → 입금 자산`
  - 금액: 수입 파랑, 지출 빨강, 이체 회색
  - 삭제된 자산은 이름 뒤에 `(삭제됨)`을 표시한다.
- 항목을 누르면 수정 화면으로 이동한다.
- 오른쪽 아래 (+) 버튼을 누르면 입력 화면으로 이동한다.

## 3. 거래 입력/수정 화면

```
┌────────────────────────────┐
│ [ 수입 ] [ 지출 ] [ 이체 ]    │
├────────────────────────────┤
│ 날짜   2026.10.09 (금)  📅   │
│ 금액   ₩ 12,000             │
│ 자산   은행 > 국민        ▼  │
│ 내용   (선택)                │
├────────────────────────────┤
│          [ 저장 ]            │
└────────────────────────────┘
```

| 항목 | 규칙 |
|---|---|
| 유형 | 상단에 수입/지출/이체 3개를 가로로 배치하고 하나를 선택. 기본값은 지출 |
| 날짜 | 기본값은 오늘. 누르면 달력(DatePicker). 시간은 기록하지 않음 |
| 금액 | 숫자 키패드. 입력 중 천 단위 쉼표 표시. 1원 이상, 최대 999,999,999,999원 |
| 자산 | `그룹 > 자산` 목록에서 선택. 삭제된 자산은 목록에 나오지 않음. 마지막으로 사용한 자산을 기본으로 채움 |
| 이체 | 자산 칸이 "출금 자산", "입금 자산" 두 칸으로 바뀜. 두 자산이 같으면 저장 불가 |
| 내용 | 선택 입력. 최대 50자 |
| 저장 | 금액과 자산(이체는 두 자산)이 모두 유효할 때만 활성화 |

### 수정 모드
- 입력 화면과 같은 화면을 쓰고, 기존 값을 채워서 연다.
- 유형도 변경할 수 있다.
- 오른쪽 위 삭제 버튼 → 확인 팝업 → 삭제.
- 삭제된 자산을 쓰는 거래를 수정할 때는, 그 자산을 그대로 유지하거나 다른 활성 자산으로 바꿀 수 있다.

## 4. 자산 탭

```
 총자산                     15,320,000
────────────────────────────────────
 은행                       14,800,000  [+]
    국민                    10,000,000
    신한                     4,800,000
 현금                          520,000  [+]
    지갑                       520,000
────────────────────────────────────
 [ + 자산 그룹 추가 ]
```

### 표시
- 상단에 총자산(모든 활성 자산 잔액의 합)을 표시한다.
- 자산 그룹별 소계와 그 아래 세부 자산의 잔액을 표시한다.
- 잔액이 마이너스면 빨간색으로 표시한다.
- 삭제된 자산은 표시하지 않는다.

### 잔액 계산
```
잔액 = 초기 잔액 + 수입 − 지출 − 이체(출금) + 이체(입금)
```
- 저장하지 않고, 거래 내역으로 매번 계산한다.
- 마이너스 잔액도 허용한다.

### 자산 그룹
- 추가: 이름 입력
- 이름 변경: 그룹을 길게 누르거나 메뉴에서 선택
- 삭제: 그룹 안에 활성 자산이 하나도 없을 때만 가능. 아니면 "자산이 남아 있어 삭제할 수 없습니다" 안내
  - 삭제된 자산이 그룹 이름을 계속 참조하므로, 그룹도 "삭제됨" 상태로 표시만 바꾼다(soft delete).

### 세부 자산
- 추가: 그룹의 [+] 버튼 → 이름, 초기 잔액 입력
- 수정: 이름, 초기 잔액, 소속 그룹 변경
- 자산을 누르면 해당 자산의 거래 내역(월별)을 보여준다.
- 삭제
  - **현재 잔액이 0원일 때만 삭제할 수 있다.** 0원이 아니면 "잔액이 0원일 때만 삭제할 수 있습니다" 안내
  - 거래 내역은 지우지 않는다. 자산은 "삭제됨" 상태로 표시만 바꾼다(soft delete).
  - 삭제된 자산은 자산 탭과 자산 선택 목록에서 사라지고, 기존 거래에는 `(삭제됨)`과 함께 이름이 남는다.

### 이름 규칙
- 자산 그룹, 세부 자산 이름은 1~20자.
- 같은 그룹 안에서 활성 자산 이름은 중복 불가. 그룹 이름도 중복 불가.

## 5. 설정 탭

### 계정
- 로그인한 Google 계정 이메일 표시
- 로그아웃

### 백업
- 마지막 백업 시각 표시 (실패 시 실패 표시)
- **지금 백업**: 즉시 드라이브에 업로드
- **드라이브에서 복원**: "현재 기기의 데이터가 백업 데이터로 바뀝니다" 확인 후 복원
- **자동 백업**: 데이터가 바뀐 뒤 앱이 백그라운드로 가면, 네트워크가 연결됐을 때 업로드 (WorkManager). 실패하면 최대 3번 다시 시도

- 백업하지 않은 변경이 있으면 "백업하지 않은 변경이 있어요" 표시
- 드라이브 권한이 없어지면 "다시 로그인해 주세요" 안내

### 디자인
- **디자인** 한 줄에 지금 테마 이름·아이콘 이름과 작은 미리보기(테마 색, 아이콘)를 보여준다.
- 누르면 **디자인 화면**이 열린다(10장). 테마와 앱 아이콘은 이 화면에서 고른다. 설정 탭에 테마를 나열하지 않는다.

### 앱 정보
- 설치된 버전 (예: `1.0 (빌드 57)`)
- 업데이트 확인 버튼 (최신이면 "최신 버전이에요"). 건너뛴 버전도 이 버튼으로는 다시 보여준다
- 오픈소스 라이선스 (Jua 폰트)

## 6. 데이터 구조

```
AssetGroup
  id          Long (PK)
  name        String
  sortOrder   Int
  deletedAt   Long?       // null이면 활성, 값이 있으면 삭제됨

Asset
  id              Long (PK)
  groupId         Long (FK → AssetGroup)
  name            String
  initialBalance  Long        // 원 단위
  sortOrder       Int
  deletedAt       Long?       // null이면 활성, 값이 있으면 삭제됨

Transaction
  id          Long (PK)
  type        INCOME | EXPENSE | TRANSFER
  date        LocalDate     // epochDay로 저장
  amount      Long          // 원 단위, 1 이상
  assetId     Long (FK → Asset)    // 수입/지출 대상, 이체의 출금 자산
  toAssetId   Long? (FK → Asset)   // 이체의 입금 자산
  memo        String        // 빈 문자열 허용
  createdAt   Long
  updatedAt   Long
```

- 금액은 부동소수점 오차를 피하기 위해 `Long`(원 단위)으로 저장한다.
- 그룹·자산은 행을 지우지 않는다(soft delete). 거래가 참조하는 자산·그룹 이름이 계속 남아야 하기 때문이다.

## 7. 백업 형식

- Drive `appDataFolder`에 파일 하나(`piggybank-backup.json`)로 저장하고, 백업할 때마다 덮어쓴다.
- 내용: 스키마 버전, 백업 시각, AssetGroup/Asset/Transaction 전체
- 복원할 때는 스키마 버전을 확인하고, 기기 DB를 비운 뒤 하나의 트랜잭션으로 넣는다.

## 8. 보안

### 저장소(공개)
- 커밋 금지: 서명 키(`*.jks`, `*.keystore`), `keystore.properties`, `local.properties`, `google-services.json`
- 서명 키와 비밀번호는 GitHub Secrets(`SIGNING_KEYSTORE_BASE64`, `SIGNING_KEYSTORE_PASSWORD`)에만 둔다. CI는 키를 임시 폴더에 풀어 쓰고 지운다.
- PR 빌드(외부 포함)에는 Secrets가 전달되지 않으므로 배포하지 않는다.
- Android OAuth는 패키지명과 서명 SHA-1로 앱을 식별하고 클라이언트 시크릿을 쓰지 않으므로, 코드가 공개돼도 다른 앱이 이 앱으로 위장할 수 없다.

### 기기
- Room DB는 SQLCipher로 암호화한다. DB 키는 Android Keystore로 보호한다.
- `android:allowBackup="false"`로 안드로이드 자동 백업을 끈다.
- 로그에 금액, 내용, 계정 정보를 출력하지 않는다. 배포 빌드가 디버그 빌드라 로그가 자동으로 지워지지 않으므로, 코드에서부터 출력하지 않는다.

### 드라이브
- `drive.appdata` 권한만 요청한다. 드라이브의 다른 파일에는 접근하지 않는다.
- 백업 파일은 해당 구글 계정과 이 앱만 접근할 수 있다. 추가 암호화는 하지 않는다.

## 9. Google Cloud 설정

- OAuth 동의 화면을 **프로덕션** 상태로 전환한다. 테스트 상태면 등록한 테스트 사용자만 로그인할 수 있다.
- Android OAuth 클라이언트 하나에 패키지명 `io.github.areswjd.piggybank`과 **고정 서명 키의 SHA-1**을 등록한다. 배포 빌드가 모두 이 키로 서명되므로 클라이언트는 하나면 된다.
- 자세한 순서: [GOOGLE_CLOUD_SETUP.md](GOOGLE_CLOUD_SETUP.md)

## 10. 디자인

- 앱 이름: **Piggy bank**
- 앱 아이콘: 9가지 중 선택(아래 "앱 아이콘"). 기본은 **1. 동전 돼지**
- 앱 속 돼지 캐릭터는 **고른 앱 아이콘 그림**을 쓴다(아래 "앱 속 캐릭터")
- 숫자는 자릿수를 맞춰 표시한다(tabular-nums)
- 다크 모드는 폰 설정을 따른다(테마마다 어두운 색 따로). 단, **H. 별밤**은 항상 어두운 화면이다. 폰 배경화면 색을 따라가는 dynamic color는 쓰지 않는다
- 시안: [Piggy bank 디자인 시안](https://claude.ai/artifact/6N2VVkgpbK75c95TjYUEhw)

### 디자인 화면 (설정 → 디자인)
- 맨 위: 뒤로 버튼과 제목 "디자인"
- 그 아래: **[테마 | 앱 아이콘]** 탭(두 탭 모두 같은 자리)
- **테마 탭**
  - 위쪽 큰 미리보기 카드: 고른 테마의 색·글꼴로 가계부 일부(월 요약, 거래 2개, 기록 버튼)를 보여준다
  - 테마 8개를 동그라미(배경색과 주 색을 반씩)로 옆으로 넘기며 고른다. 동그라미 아래에 이름. A에는 "기본" 표시
  - 동그라미를 누르면 미리보기만 바뀐다. 아래 **이 디자인으로 바꾸기**를 눌러야 앱 전체에 적용된다
- **앱 아이콘 탭**
  - 위쪽: 홈 화면에서 어떻게 보이는지 미리보기(배경 위에 다른 앱 자리와 함께)
  - 아이콘 9개를 3×3 격자로 보여주고 하나를 고른다
  - 아래 **이 아이콘으로 바꾸기**를 눌러야 바뀐다. 바꾼 뒤 "아이콘을 바꿨어요. 홈 화면에 보이기까지 조금 걸릴 수 있어요" 안내
- 지금 쓰는 것을 고른 상태면 버튼을 누를 수 없고 "지금 쓰는 디자인이에요" / "지금 쓰는 아이콘이에요"로 보인다

## 12. 빌드·설치·업데이트

### 사용 환경
- 사용자는 가족이고, 개발자가 직접 설치해 주고 관리한다. 개발자 본인은 설치하지 않는다.
- 데이터를 저장하는 구글 계정(가족 본인 계정)과 개발자 계정은 다를 수 있다.
- 그래서 개발 버전 하나만 배포한다. 정식·개발 채널을 나누지 않는다.

### 자동 빌드 (GitHub Actions `android.yml`)
- 실행 시점: 모든 브랜치 push, pull_request, 수동 실행
- 한 번에 하나만 실행한다(릴리스를 지우고 만드는 작업이 겹치지 않게).
- 순서: 단위 테스트 → lint → 디버그 APK 빌드 → APK 보관(Artifacts)
- PR 빌드가 아니고 서명 키 Secrets가 있으면 GitHub 릴리스 **`dev-latest`**(사전 릴리스)를 지우고 새로 만든다.
  - 첨부 파일: `piggybank.apk`
  - 제목: `개발 버전 (빌드 N)`
  - 설명 첫 줄: `versionCode: N` (앱의 업데이트 확인에 쓴다). 둘째 줄부터는 이번 빌드의 커밋 메시지(`Co-Authored-By:` 같은 꼬리말 줄은 뺀다)
- ⚠️ 어느 브랜치든 push하면 바로 가족 폰에 업데이트 알림이 간다.

### 버전과 서명
- `versionCode` = GitHub Actions 빌드 번호(`GITHUB_RUN_NUMBER`). 로컬 빌드는 1
- `versionName` = `1.0` (화면에는 `1.0 (빌드 N)`으로 표시)
- 배포하는 것은 **디버그 빌드**다. 고정 서명 키로 서명해서 항상 덮어쓰기 업데이트가 된다.
- 패키지 이름은 하나: `io.github.areswjd.piggybank` (디버그용 `.debug` 접미사를 없앤다)

### 최초 설치
- 설치 링크(항상 최신 빌드): `https://github.com/Ares-wjd/piggy-bank/releases/download/dev-latest/piggybank.apk`
- 가족 폰에서 링크를 열어 내려받고 "출처를 알 수 없는 앱 설치"를 허용한 뒤 설치한다.

### 앱 안 업데이트
- 확인 시점: **앱을 켤 때마다**(로그인 여부와 무관, 횟수 제한 없음) + 설정 탭의 **업데이트 확인** 버튼
- `https://api.github.com/repos/Ares-wjd/piggy-bank/releases/tags/dev-latest`를 조회한다. 설명의 `versionCode: N`이 지금 앱의 versionCode보다 크고 `.apk` 첨부가 있으면 새 버전이다.
- 새 버전이 있으면 팝업을 띄운다(강제하지 않음).
  - 내용: `빌드 N`, 변경 내용(설명 둘째 줄부터)
  - 버튼: **[업데이트] [이 버전 건너뛰기] [나중에]**
  - **나중에**: 다음에 앱을 켤 때 다시 묻는다.
  - **이 버전 건너뛰기**: 그 빌드는 자동 확인에서 다시 묻지 않는다. 더 새 빌드가 나오면 묻는다. 건너뛴 빌드는 SharedPreferences에 저장한다.
- 업데이트를 누르면 다음 순서로 진행한다.
  1. 앱 안에서 APK를 내려받는다(진행률 표시).
  2. 크기, 패키지 이름, versionCode를 확인한다.
  3. 안드로이드 설치 화면을 띄운다. 서명이 같은지는 설치할 때 안드로이드가 확인한다.
  - 처음 한 번은 "이 출처 허용" 권한이 필요하다. 앱이 설정 화면으로 안내하고, 돌아오면 설치를 이어간다.
  - 실패하면 **[다시 시도] [닫기]**
- 업데이트해도 기기 데이터는 그대로 유지된다.
